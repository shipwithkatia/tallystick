with every tool_call_id and tool name stripped:
  identical              664  (96%)
  artifacts read as the wrong kind  35
  With neither, a result can only be matched to its call by the
  order the calls were declared in. Three of the laundering
  defects found in review of this release lived on that matching
  code - and this corpus can decide almost nothing about it:
       204  parallel tool batches
       118  of them calling more than one distinct tool
         1  of those mixing a tool that hands back the model's
            own text with one that does not - the only shape where
            a mis-assignment can move an artifact across the root
            line and change a verdict
  So this pass is a regression guard, not evidence: the coverage for
  that code is in tests/test_convert.py, written from the failing
  inputs review found, because the corpus does not contain them.

with no --tool-returns-model-text flags at all:
  identical              493  (71%)
  The headline above names this corpus's four echo tools. Without
  them a final_answer tool's output is a root, and the two readers
  part on a third of the corpus. That is not a defect in either:
  it is the size of what only the operator knows, and the reason
  the flag exists.

  -> worse, and not for the obvious reason: most of what the flag
     would demote is web text surfaced through the interpreter, not
     a computed value - and a few are echoes the native reader's own
     8-character guard let through. The flag is for a tool that
     ALWAYS hands back the model's words. An interpreter does not.
